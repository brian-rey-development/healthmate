# v0.3 · Visits

Not started.

## Goal

Capture what happens around doctor visits, including documents.

## Scope

**In.** Encounters with notes before and after, logged by text, voice or form. Encrypted file uploads attached to encounters, and cleanup of orphaned files.

**Out.** Reading or extracting file contents, which starts in v0.5. File contents never reach the model in this release.

## Entry criteria

- [ ] v0.2 shipped, so files are encrypted from the first upload

## Decisions

- [ ] Whether a file is its own record or an attachment
- [ ] Maximum file size and whether encryption streams
- [ ] Recovery when storage and database disagree after a failed upload
- [ ] Local object storage, either Supabase Storage, which is in the stack but disabled, or MinIO

## Work plan

- [ ] `core/domain` · Encounter entry with pre and post notes, and file references with their state. Pure tests.
- [ ] `core/ports` and `core/application` · File storage port, upload as a two-phase operation that commits the record only after the file is stored. Unit tests against `core/testing`, including a crash between phases.
- [ ] `database` · Encounter and file tables, generated migration, encrypted storage adapter. Integration tests.
- [ ] `agent` · Tools to propose encounters and attach notes. Eval cases added to Capture and Clarify.
- [ ] `apps/api` · Upload and encounter routes, and a scheduled job that deletes orphaned files. Route tests.
- [ ] `apps/mobile` · Encounter form, upload and encounter view on the timeline.
- [ ] `apps/telegram` · Encounter capture by text and voice, and file upload.

## Acceptance criteria

- [ ] An encounter can be logged by text, voice or form, with pre and post notes
- [ ] Uploaded files are encrypted at rest and unreadable without the key
- [ ] Killing the process mid-upload leaves no record pointing to a missing file
- [ ] Orphaned files are cleaned up automatically
- [ ] File contents never reach the model
- [ ] Release checklist complete

## Risks

| Risk | Mitigation |
|---|---|
| Storage and database drift apart | Two-phase upload plus the orphan cleanup job, both tested with forced failures |
| Large files exhaust memory during encryption | File size limit and streaming decided before implementation |

## Demo script

1. Log "Seeing Dr. Ruiz Thursday about the headaches" as a pre-visit note.
2. After the visit, add post notes by voice and upload the doctor's letter.
3. Show the encounter on the timeline and the encrypted file in storage.
