# v0.8 · Visit brief

Not started.

## Goal

Walk into appointments prepared.

## Scope

**In.** Selecting records for a visit, generating a brief where every sentence cites a record, editing with generated and edited text kept distinct, and exporting.

**Out.** Sending briefs to anyone directly, and encrypted export formats.

## Entry criteria

- [ ] v0.7 shipped, so the read agent can cite any record kind

## Decisions

- [ ] Fixed structure or free-form
- [ ] Export format
- [ ] How much source detail an export includes

## Work plan

- [ ] `core/domain` · Brief with sections, sentences linked to cited records, and an origin per sentence of generated or edited. Pure tests.
- [ ] `core/application` · Create, edit and export briefs, with the export written to the audit log. Unit tests.
- [ ] `agent` · Brief generation from selected records only, with sentence-level citation validation. Brief eval suite.
- [ ] `db` · Brief tables and migration. Integration tests.
- [ ] `apps/mobile` · Record selection, brief editor and export with an unencrypted-file warning.

## Acceptance criteria

- [ ] Every sentence in a generated brief cites at least one record
- [ ] Only selected records are used
- [ ] Edited text is distinguishable from generated text
- [ ] Every export appears in the access log
- [ ] The person is told before exporting that the file is not encrypted
- [ ] Brief eval suite passes
- [ ] Release checklist complete

## Risks

| Risk | Mitigation |
|---|---|
| A brief contains a claim from outside the selection | Citation validation rejects any sentence citing an unselected record |
| An exported file leaks after leaving the app | Explicit warning before export, and the export is audited |

## Demo script

1. Select the last three months of headaches and the glucose results.
2. Generate a brief, open two citations, and edit one sentence.
3. Export it, then show the export in the access log.
